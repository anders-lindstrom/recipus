# AI-tillägg (bild, text, röst) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the household put many varor on a list in one gesture — from a Bring screenshot, a pasted clump of text, or a spoken sentence — reviewed in a dialog before anything is written.

**Architecture:** An Anthropic call turns messy input into clean Swedish lines and nothing more; the *existing* voice engine (`interpretUtterance` → `resolveSpokenItems` → `dedupeResolutions`) decides which vara each line means, against `loadMatchCandidates()` so aliases still work. A read-only endpoint returns rows; the client renders them in a `RecipeAddSheet`-shaped dialog and writes ops through the list's normal optimistic `dispatch`.

**Tech Stack:** Next.js 16 App Router, Hono + `@hono/zod-openapi`, `@anthropic-ai/sdk` (`messages.parse` + `zodOutputFormat`), Drizzle, Tailwind 4, vitest (node env), Playwright.

**Spec:** [`docs/superpowers/specs/2026-08-13-ai-add-design.md`](../specs/2026-08-13-ai-add-design.md)

## Global Constraints

- **Language:** every string a person reads is Swedish. Code, comments and commit messages are English, as in the rest of `src/`.
- **Model:** `claude-opus-5`. No `temperature`, no `top_p` — mirror `src/lib/recipes/llm.ts` exactly.
- **The model never sees or returns a `catalogItemId`.** Matching is `matchIngredient` against `loadMatchCandidates()`, nowhere else.
- **No failure path throws out of the LLM layer.** Missing key, refusal, network error, malformed output → `null`.
- **`/api/ai/*` writes nothing.** No ops, no catalog rows. Every write happens client-side after the person presses the button.
- **Tests:** vitest `include` is `src/**/*.test.ts` — `.ts` only, `environment: "node"`. There is no DOM in unit tests; components are proven by Playwright. Pure logic therefore lives in `*-model.ts` files beside components, as `list-model.ts` and `recipe-model.ts` already do.
- **Commits:** Conventional Commits, imperative, lowercase, no trailing period, no AI attribution. Commit with `git_agent commit`, not `git commit`.
- **Run after each task:** `pnpm test && pnpm tsc --noEmit && pnpm lint`.

```ts
/**
 * The AI front door: messy input, clean Swedish lines out.
 *
 * Deliberately the least clever part of this feature. The model is not asked
 * which vara a word means — `matchIngredient` against `loadMatchCandidates()`
 * answers that, and it is the same matcher the add bar, the recipe importer and
 * the voice path already use. Handing the model 341 varor and asking for ids
 * would put a second reading of "which vara is this" in the codebase, and the
 * codebase's whole sync story rests on there being one of everything.
 *
 * Shaped like `src/lib/recipes/llm.ts` on purpose, including the rule that
 * matters most: nothing here throws. Every failure — no key, a refusal, a dead
 * network, output that does not fit the schema — comes back as `null`, and the
 * caller decides what to do about it. For text there is a real answer (the
 * deterministic voice parser); for an image there is not.
 */

import Anthropic from "@anthropic-ai/sdk";
import { zodOutputFormat } from "@anthropic-ai/sdk/helpers/zod";
import { z } from "zod";

export const AI_ADD_MODEL = "claude-opus-5";
const MAX_TOKENS = 4000;
/** A pasted clump is a shopping list, not a novel. Caps prompt cost. */
const MAX_TEXT_CHARS = 8_000;

/** Where on the input a line was read. See the spec, §2.1. */
export type LineGroup = "list" | "other";

export interface ParsedLine {
  /** One thing, in Swedish, with any quantity left in place: "2 l mjölk". */
  text: string;
  group: LineGroup;
}

export type AiInput =
  | { kind: "text"; text: string }
  | { kind: "image"; data: string; mediaType: string };

const LinesSchema = z.object({
  lines: z.array(
    z.object({
      text: z.string(),
      group: z.enum(["list", "other"]),
    }),
  ),
});

const SYSTEM_PROMPT = `Du läser en inköpslista och plockar ut sakerna som ska köpas.

Regler:
- Ett element per sak. Slå aldrig ihop två varor på en rad.
- Skriv raden på svenska, med mängden kvar i texten ("2 l mjölk", "3 st ägg").
  Saknas mängd, skriv bara varan.
- Behåll hushållets egna ord. Översätt inte, förfina inte, byt inte ut ett
  märkesnamn mot en generisk vara.
- group är "list" för rader som står på själva listan.
- group är "other" för allt annat du kan läsa: förslagsrutnät ("senast
  använda"), gråmarkerade rader, redan avbockade rader, och reklam.
- Hitta aldrig på varor. Står det ingenting läsbart, svara med en tom lista.
- Skalstreck, rubriker, klockslag, sidnummer och appens egna knappar är inte
  varor.`;

/**
 * Read whatever came in as the things it names.
 *
 * `null` means "the model could not help", which is a different answer from an
 * empty array ("the model looked and there was nothing there") — the caller
 * shows a different message for each, and conflating them is how a person ends
 * up retrying a request that will never work.
 */
export async function parseInput(input: AiInput): Promise<ParsedLine[] | null> {
  if (!process.env.ANTHROPIC_API_KEY) return null;

  const client = new Anthropic();
  const content =
    input.kind === "text"
      ? [{ type: "text" as const, text: input.text.slice(0, MAX_TEXT_CHARS) }]
      : [
          {
            type: "image" as const,
            source: {
              type: "base64" as const,
              media_type: input.mediaType,
              data: input.data,
            },
          },
        ];

  let response;
  try {
    response = await client.messages.parse({
      model: AI_ADD_MODEL,
      max_tokens: MAX_TOKENS,
      system: SYSTEM_PROMPT,
      messages: [{ role: "user", content }],
      output_config: { format: zodOutputFormat(LinesSchema) },
    });
  } catch {
    return null;
  }

  // Checked before parsed_output is read: a refusal can still carry a
  // meaningless parsed_output, exactly as recipes/llm.ts documents.
  if (response.stop_reason === "refusal") return null;

  const parsed = response.parsed_output;
  if (!parsed) return null;

  return parsed.lines
    .map((line) => ({ text: line.text.trim(), group: line.group }))
    .filter((line) => line.text.length > 0);
}
```

```ts
/**
 * Model lines → rows the dialog can draw.
 *
 * Pure, and it borrows the entire voice engine rather than reimplementing any
 * of it. Each line goes through `interpretUtterance`, which is what makes "2 l"
 * mean here exactly what it means in the add bar, splits "salt och peppar" into
 * two varor, and peels off a carrier phrase the model left in ("lägg till ägg").
 * Then `resolveSpokenItems` matches against the alias-expanded candidate list —
 * the only matcher that consults aliases, and therefore the only one through
 * which an English word can reach a Swedish katalog.
 *
 * The one thing this adds on top is the group, which the voice path has no
 * notion of because a speaker cannot point at a suggestion grid.
 */

import type { Amount, Id } from "@/lib/domain";
import type { MatchCandidate } from "@/lib/ingredients";
import { normalizeName } from "@/lib/utils";
import { interpretUtterance } from "@/lib/voice/interpret";
import { resolveSpokenItems } from "@/lib/voice/resolve";
import type { LineGroup, ParsedLine } from "./parse";

export interface AiRow {
  /** Stable within one parse, so React keys and the ticked set can use it. */
  id: string;
  /** The words as they were read, kept for showing back what failed. */
  said: string;
  /** The name with any quantity peeled off. */
  name: string;
  amount: Amount | null;
  /** null means no vara answered to this — the dialog offers to create one. */
  catalogItemId: Id | null;
  group: LineGroup;
}

export function buildRows(
  lines: readonly ParsedLine[],
  candidates: MatchCandidate[],
): AiRow[] {
  const rows: AiRow[] = [];
  /*
   * Two indexes, because a row is deduped by whichever key it has.
   *
   * `dedupeResolutions` in the voice path folds matched rows by vara and
   * deliberately leaves unknowns alone — right there, where an unknown is only
   * ever read aloud. Here an unknown is an offer to CREATE a vara, so two
   * spellings of one unmatched word would create the same thing twice, or
   * present the person with the same decision twice. Normalized names, so
   * "Oatly iKaffe" and "oatly ikaffe" are one offer.
   */
  const byItem = new Map<Id, number>();
  const byName = new Map<string, number>();

  for (const line of lines) {
    for (const spoken of interpretUtterance(line.text)) {
      const [resolution] = resolveSpokenItems([spoken], candidates);
      if (!resolution) continue;

      const catalogItemId =
        resolution.status === "matched" ? resolution.catalogItemId : null;
      const key = catalogItemId ?? normalizeName(spoken.name);
      const index = catalogItemId ? byItem.get(catalogItemId) : byName.get(key);

      if (index !== undefined) {
        /*
         * Seen already. The first mention keeps its amount — it is the one the
         * person wrote first — but a later "list" sighting promotes the row out
         * of the suggestion grid. A vara that is both on the list and in the
         * grid below it is on the list, and must arrive ticked.
         */
        if (line.group === "list") rows[index]!.group = "list";
        continue;
      }

      const at = rows.length;
      rows.push({
        id: `r${at}`,
        said: spoken.said,
        name: spoken.name,
        amount: spoken.amount,
        catalogItemId,
        group: line.group,
      });
      if (catalogItemId) byItem.set(catalogItemId, at);
      else byName.set(key, at);
    }
  }

  return rows;
}
```

```ts
/**
 * A shared image, held just long enough to be looked at.
 *
 * Android's share target is a POST navigation, so the image arrives at the
 * server before the app is even open — but the parse belongs to the dialog the
 * person is about to see, not to the redirect. So the bytes wait here under a
 * random token, and the page fetches them back through `/api/ai/parse` a moment
 * later.
 *
 * In memory, deliberately. The household runs one container; a token that does
 * not survive a restart costs one re-share, and the alternative — a screenshot
 * of your shopping written to disk or to Postgres — is a durable copy of
 * something nobody asked to keep. Ten minutes and five slots is well past what
 * a share-then-open takes and nowhere near a leak.
 *
 * `take` empties the slot and checks the actor. Neither guard is theatre: the
 * app is behind Authelia, but a token in a URL is the one part of this that
 * lands in browser history and could be pasted into a chat.
 */

import { randomBytes } from "node:crypto";

export const SHARE_TTL_MS = 10 * 60 * 1000;
export const SHARE_CAPACITY = 5;

export interface SharedImage {
  /** base64, no data-URL prefix. */
  data: string;
  mediaType: string;
}

interface Slot extends SharedImage {
  actor: string;
  at: number;
}

const slots = new Map<string, Slot>();

/** Test seam. Not called by the app — the store is process-lifetime. */
export function resetSharedImages(): void {
  slots.clear();
}

function evictStale(now: number): void {
  for (const [token, slot] of slots) {
    if (now - slot.at > SHARE_TTL_MS) slots.delete(token);
  }
  // Map preserves insertion order, so the first key is the oldest put.
  while (slots.size >= SHARE_CAPACITY) {
    const oldest = slots.keys().next();
    if (oldest.done) break;
    slots.delete(oldest.value);
  }
}

export function putSharedImage(
  image: SharedImage & { actor: string },
  now: Date = new Date(),
): string {
  evictStale(now.getTime());
  const token = randomBytes(24).toString("base64url");
  slots.set(token, {
    data: image.data,
    mediaType: image.mediaType,
    actor: image.actor,
    at: now.getTime(),
  });
  return token;
}

export function takeSharedImage(
  token: string,
  actor: string,
  now: Date = new Date(),
): SharedImage | null {
  const slot = slots.get(token);
  if (!slot) return null;
  if (now.getTime() - slot.at > SHARE_TTL_MS) {
    slots.delete(token);
    return null;
  }
  // Deliberately not consumed on a mismatch: the rightful owner is probably
  // mid-open, and punishing them for someone else's bad token is worse.
  if (slot.actor !== actor) return null;
  slots.delete(token);
  return { data: slot.data, mediaType: slot.mediaType };
}
```

```ts
/**
 * The whole AI-add read path, in one function.
 *
 * Reads. Never writes. That separation is the difference between this and
 * `voice-ingest.ts` next door, and it is not incidental: the voice path answers
 * a person with no screen, so it must decide AND act, while this one answers a
 * dialog that is about to show its work. Nothing here may put a vara on a list.
 */

import type { AiRow } from "@/lib/ai-add";
import { buildRows, parseInput } from "@/lib/ai-add";
import { interpretUtterance } from "@/lib/voice/interpret";
import { loadMatchCandidates } from "./match-candidates";

export type AiAddInput =
  | { kind: "text"; text: string }
  | { kind: "image"; data: string; mediaType: string };

export interface AiAddResult {
  rows: AiRow[];
  /**
   * False when the model was unavailable and text was read deterministically.
   * The dialog says so, rather than letting a person wonder why "grejer till
   * tacos" produced nothing.
   */
  usedModel: boolean;
}

export async function parseForList(input: AiAddInput): Promise<AiAddResult> {
  const lines = await parseInput(input);
  const candidates = await loadMatchCandidates();

  if (lines) return { rows: buildRows(lines, candidates), usedModel: true };

  /*
   * The model could not help. For text there is still a real answer: the
   * deterministic parser that has been putting "ägg, mjölk och keso" on this
   * household's list from Home Assistant for months. It reads a comma-separated
   * sentence perfectly well and only loses the loose phrasing a model would
   * have tidied.
   *
   * `interpretUtterance` splits on its own, so the raw text goes in as ONE
   * line rather than being pre-split here — two splitters would disagree about
   * "salt och peppar" eventually.
   */
  if (input.kind === "text") {
    const rows = buildRows(
      interpretUtterance(input.text).map((spoken) => ({
        text: spoken.said,
        group: "list" as const,
      })),
      candidates,
    );
    return { rows, usedModel: false };
  }

  // An image without a model is simply unreadable. The route turns this into a
  // 503 with a sentence that says which knob is missing.
  return { rows: [], usedModel: false };
}
```

```ts
import { OpenAPIHono, createRoute, z } from "@hono/zod-openapi";
import { parseForList } from "@/lib/services/ai-add";
import { takeSharedImage } from "@/lib/services/share-inbox";
import type { ApiEnv } from "..";
import { amountSchema, errorSchema, jsonBody, jsonRes } from "../schemas";

/**
 * Reading a photo, a paste or a spoken sentence as varor.
 *
 * Inside the Authelia gate, unlike `/api/voice` — the caller is a browser with
 * a session, so inventing a second secret would be inventing a second thing to
 * leak. And unlike `/api/voice`, this endpoint writes NOTHING. It answers a
 * dialog, and the dialog's own button writes the ops through the list's normal
 * optimistic path.
 */

/** ~8 MB of base64 is ~6 MB of JPEG; the client sends far less. See §3. */
const MAX_IMAGE_CHARS = 8_000_000;

const parseBody = z
  .discriminatedUnion("kind", [
    z.object({ kind: z.literal("text"), text: z.string().min(1).max(8000) }),
    z.object({
      kind: z.literal("image"),
      data: z.string().min(1).max(MAX_IMAGE_CHARS),
      mediaType: z.enum(["image/jpeg", "image/png", "image/webp"]),
    }),
    z.object({ kind: z.literal("share"), token: z.string().min(1).max(128) }),
  ])
  .openapi("AiParseRequest");

const rowSchema = z.object({
  id: z.string(),
  said: z.string(),
  name: z.string(),
  amount: amountSchema.nullable(),
  catalogItemId: z.string().nullable(),
  group: z.enum(["list", "other"]),
});

const parseResult = z
  .object({
    rows: z.array(rowSchema),
    usedModel: z
      .boolean()
      .describe("False when text was read deterministically because the model was unavailable"),
  })
  .openapi("AiParseResult");

export function aiRoutes() {
  const app = new OpenAPIHono<ApiEnv>();

  app.openapi(
    createRoute({
      method: "post",
      path: "/parse",
      tags: ["ai"],
      description:
        "Read an image, a clump of text or a transcript as the varor it names. Writes nothing — the rows come back for review.",
      request: { body: jsonBody(parseBody) },
      responses: {
        200: jsonRes(parseResult, "What was understood"),
        404: jsonRes(errorSchema, "The shared image is gone"),
        503: jsonRes(errorSchema, "ANTHROPIC_API_KEY is not configured"),
      },
    }),
    async (c) => {
      const body = c.req.valid("json");

      if (body.kind === "share") {
        const image = takeSharedImage(body.token, c.get("actor"));
        if (!image) {
          return c.json(
            { error: "Den delade bilden är borta. Dela den igen." },
            404,
          );
        }
        if (!process.env.ANTHROPIC_API_KEY) {
          return c.json({ error: "Bildtolkning är inte konfigurerad (ANTHROPIC_API_KEY)." }, 503);
        }
        return c.json(await parseForList({ kind: "image", ...image }), 200);
      }

      if (body.kind === "image" && !process.env.ANTHROPIC_API_KEY) {
        // Text has a way through without a key; an image does not, and saying
        // which knob is missing beats an empty result that looks like a bug.
        return c.json({ error: "Bildtolkning är inte konfigurerad (ANTHROPIC_API_KEY)." }, 503);
      }

      return c.json(await parseForList(body), 200);
    },
  );

  return app;
}
```

```ts
import { headers } from "next/headers";
import { AuthError, authenticate } from "@/lib/auth";
import { putSharedImage } from "@/lib/services/share-inbox";

/**
 * The one share target, triaging what was shared.
 *
 * A manifest may declare exactly one `share_target`, and images require
 * `method: "POST"` with `multipart/form-data`. That would have cost the recipe
 * importer its own GET target, so both now arrive here and are sent onward: a
 * file to the list's AI dialog, a link to the recipe importer, which keeps
 * working exactly as it did.
 *
 * A route handler rather than the service worker, deliberately. The first
 * design put this in `sw.js`'s fetch handler with the file stashed in
 * IndexedDB, and `sw.js`'s own comments explain why that is the wrong place for
 * a rarely-run code path: a bad worker is "a self-inflicted,
 * unrecoverable-from-inside state" because the app's code never runs to fix it.
 * This can be tested, deployed and rolled back like any other route, and it
 * works the first time the app is installed, before any worker is active.
 *
 * 303 rather than 302: the share arrives as POST, and only 303 tells the
 * browser to follow it with GET. A 302 re-POSTs to a page that cannot take it.
 */

const ACCEPTED = new Set(["image/jpeg", "image/png", "image/webp"]);

function seeOther(path: string): Response {
  return new Response(null, { status: 303, headers: { Location: path } });
}

export async function POST(request: Request): Promise<Response> {
  // Who shared it, so `takeSharedImage` can refuse to hand the image to anybody
  // else. A share from a lapsed session goes to the app, which shows its own
  // signed-out banner over a working offline list — far better than an error
  // page at the end of a share.
  let actor: string | null = null;
  try {
    actor = authenticate(await headers()).autheliaUser;
  } catch (err) {
    if (!(err instanceof AuthError)) throw err;
  }

  let form: FormData;
  try {
    form = await request.formData();
  } catch {
    return seeOther("/");
  }

  const file = form.get("image");
  if (actor && file instanceof File && file.size > 0 && ACCEPTED.has(file.type)) {
    const data = Buffer.from(await file.arrayBuffer()).toString("base64");
    const token = putSharedImage({ data, mediaType: file.type, actor });
    return seeOther(`/?ai=share&t=${encodeURIComponent(token)}`);
  }

  // Not a file — the recipe importer's existing GET contract, rebuilt from the
  // form fields. It already pulls a URL out of a sentence in `text`, so both
  // are passed through untouched.
  const url = typeof form.get("url") === "string" ? String(form.get("url")) : "";
  const text = typeof form.get("text") === "string" ? String(form.get("text")) : "";
  const title = typeof form.get("title") === "string" ? String(form.get("title")) : "";
  if (url || text || title) {
    const params = new URLSearchParams();
    if (url) params.set("url", url);
    if (text) params.set("text", text);
    if (title) params.set("title", title);
    return seeOther(`/recept/importera?${params.toString()}`);
  }

  return seeOther("/");
}
```

```ts
 *
 * Two exceptions, for opposite reasons. The suggestion grid ("other") was never
 * on anybody's list. And a vara ALREADY on the list must not be re-added: the
 * server retracts a purchase of the same vara from the last half hour when one
 * comes back, so ticking it would erase köphistorik from a shop that happened
 * twenty minutes ago.
 */
export function initialTicked(
  rows: readonly AiRow[],
  onList: ReadonlySet<Id>,
): Set<string> {
  const ticked = new Set<string>();
  for (const r of rows) {
    if (r.group !== "list") continue;
    if (r.catalogItemId && onList.has(r.catalogItemId)) continue;
    ticked.add(r.id);
  }
  return ticked;
}

export interface AiAddPlan {
  /** Varor to mint first — the adds below reference them. */
  creates: CatalogItem[];
  adds: Array<{ catalogItemId: Id; amount: Amount | null }>;
}

/**
 * The ticked rows, as the ops they imply.
 *
 * An unmatched row becomes a vara named exactly what was read, filed in Övrigt
 * — the same answer `newVaraLike` gives with nothing to inherit from, because
 * guessing an aisle sends you to the wrong end of the shop permanently.
 *
 * The id is `slugify(name)`, which is what makes the reuse guard work: a word
 * that already exists resolves to the vara that already exists instead of
 * replacing it, exactly as `ensureVara` does for the add bar.
 */
export function planAdditions(
  rows: readonly AiRow[],
  ticked: ReadonlySet<string>,
  catalog: Record<Id, CatalogItem>,
): AiAddPlan {
  const creates: CatalogItem[] = [];
  const adds: AiAddPlan["adds"] = [];
  const seen = new Set<Id>();

  for (const row of rows) {
    if (!ticked.has(row.id)) continue;

    let id = row.catalogItemId;
    if (!id) {
      const name = row.name.trim();
      if (!name) continue;
      id = slugify(name);
      if (!catalog[id] && !seen.has(id)) creates.push(newVaraLike(id, name));
    }

    // One vara, one tile: the list's own invariant. A second add would be a
    // no-op the confirmation would then cheerfully count.
    if (seen.has(id)) continue;
    seen.add(id);
    adds.push({ catalogItemId: id, amount: row.amount });
  }

  return { creates, adds };
}

/**
 * The size a photo is shrunk to before it is uploaded.
 *
 * A modern phone screenshot is 12 megapixels of a list containing perhaps forty
 * words. Sending it whole costs the shopper's uplink and the prompt's budget
 * for nothing — the text is legible far below that. Pure so the arithmetic can
 * be tested; the canvas that applies it lives in `lib/client/image-file.ts`.
 */
export function fitWithin(
  w: number,
  h: number,
  max: number,
): { width: number; height: number } {
  const longest = Math.max(w, h);
  if (longest <= max) return { width: w, height: h };
  const scale = max / longest;
  // Never zero: a canvas of width 0 throws, and a sliver of an image is still
  // an image.
  return {
    width: Math.max(1, Math.round(w * scale)),
    height: Math.max(1, Math.round(h * scale)),
  };
}
```

```ts
"use client";

import { useCallback, useEffect, useRef, useState } from "react";

/**
 * Saying what you need, in the browser you already have open.
 *
 * `SpeechRecognition` rather than a recording uploaded for transcription, and
 * the reasoning is the same one that shaped `docs/voice.md`: the useful thing
 * is Swedish, and this is the only Swedish speech path that costs no new
 * secret, no new provider and no new bill. Chrome on Android and Safari on iOS
 * both have it. Firefox has none, and there the button is not drawn at all — a
 * control that cannot work is worse than an absent one, because it teaches you
 * the app is broken rather than that the feature is elsewhere.
 *
 * Whatever is heard lands in the textarea, which means a misheard word is
 * editable before anything is parsed, and the transcript then goes through the
 * same model pass as a paste. No audio leaves as a file.
 */

interface SpeechRecognitionLike {
  lang: string;
  continuous: boolean;
  interimResults: boolean;
  start: () => void;
  stop: () => void;
  onresult: ((event: SpeechRecognitionEventLike) => void) | null;
  onend: (() => void) | null;
  onerror: (() => void) | null;
}

interface SpeechRecognitionEventLike {
  resultIndex: number;
  results: ArrayLike<ArrayLike<{ transcript: string }> & { isFinal: boolean }>;
}

type Ctor = new () => SpeechRecognitionLike;

function ctor(): Ctor | null {
  if (typeof window === "undefined") return null;
  const w = window as unknown as {
    SpeechRecognition?: Ctor;
    webkitSpeechRecognition?: Ctor;
  };
  return w.SpeechRecognition ?? w.webkitSpeechRecognition ?? null;
}

export function useSpeech(onTranscript: (text: string) => void): {
  supported: boolean;
  listening: boolean;
  toggle: () => void;
} {
  // Read once, after mount. Reading it during render would disagree with the
  // server's answer and tear the hydration.
  const [supported, setSupported] = useState(false);
  const [listening, setListening] = useState(false);
  const recognition = useRef<SpeechRecognitionLike | null>(null);
  // The callback through a ref, so restarting recognition is not a dependency
  // of every keystroke in the textarea above it.
  const sink = useRef(onTranscript);
  sink.current = onTranscript;

  useEffect(() => {
    setSupported(ctor() !== null);
    return () => recognition.current?.stop();
  }, []);

  const toggle = useCallback(() => {
    if (recognition.current) {
      recognition.current.stop();
      recognition.current = null;
      setListening(false);
      return;
    }

    const Recognition = ctor();
    if (!Recognition) return;

    const rec = new Recognition();
    rec.lang = "sv-SE";
    rec.continuous = true;
    // The words appear as they are said. A silent five seconds followed by a
    // paragraph reads as a hang.
    rec.interimResults = true;
    rec.onresult = (event) => {
      let heard = "";
      for (let i = event.resultIndex; i < event.results.length; i++) {
        const result = event.results[i];
        if (result?.[0]) heard += result[0].transcript;
      }
      if (heard.trim()) sink.current(heard.trim());
    };
    rec.onend = () => {
      recognition.current = null;
      setListening(false);
    };
    rec.onerror = () => {
      recognition.current = null;
      setListening(false);
    };

    recognition.current = rec;
    rec.start();
    setListening(true);
  }, []);

  return { supported, listening, toggle };
}
```

```ts
"use client";

import { fitWithin } from "@/components/ai-add-model";

/** The long edge a photo is shrunk to. See `fitWithin`'s own comment. */
const MAX_EDGE = 1600;
const QUALITY = 0.8;

/**
 * A picked or shared photo, small enough to send from a phone.
 *
 * Always re-encoded to JPEG, whatever came in: a PNG screenshot of a shopping
 * list is several megabytes of losslessly-encoded flat colour, and the model
 * reads the JPEG exactly as well. The arithmetic is `fitWithin`, which is pure
 * and tested; this is the canvas around it.
 */
export async function fileToParseInput(
  file: File,
): Promise<{ data: string; mediaType: "image/jpeg" }> {
  const bitmap = await createImageBitmap(file);
  const { width, height } = fitWithin(bitmap.width, bitmap.height, MAX_EDGE);

  const canvas = document.createElement("canvas");
  canvas.width = width;
  canvas.height = height;
  const context = canvas.getContext("2d");
  if (!context) throw new Error("Kunde inte läsa bilden.");
  context.drawImage(bitmap, 0, 0, width, height);
  bitmap.close();

  const dataUrl = canvas.toDataURL("image/jpeg", QUALITY);
  // Strip "data:image/jpeg;base64," — the API takes raw base64.
  return { data: dataUrl.slice(dataUrl.indexOf(",") + 1), mediaType: "image/jpeg" };
}
```

```tsx
import type { CatalogItem, Id } from "@/lib/domain";
import { fileToParseInput } from "@/lib/client/image-file";

import { ItemIcon } from "./icon";

/**
 * Putting a whole list on the list.
 *
 * The same contract as `RecipeAddSheet`, deliberately down to the row markup:
 * you see what is about to happen, you untick what you did not mean, and one
 * button does the rest. A screenshot of somebody else's app, a clump of typed
 * text and a sentence said out loud all arrive at this one screen, because they
 * are all the same question — "is this what you meant?" — and answering it
 * three different ways would be three things to learn.
 *
 * What it never does is write. The parse is a read; the ops are the caller's,
 * dispatched through the list's ordinary optimistic path.
 */

type Phase =
  | { step: "collecting" }
  | { step: "parsing" }
  | { step: "reviewing"; rows: AiRow[]; usedModel: boolean }
  | { step: "error"; message: string };

export interface AiAddSheetProps {
  listName: string;
  catalog: Record<Id, CatalogItem>;
  /** What is already on the list — those rows arrive unticked. */
  onListItemIds: Set<Id>;
  /** Present when a share opened this: parse that image on mount. */
  shareToken?: string;
  onCancel: () => void;
  onConfirm: (plan: AiAddPlan) => void;
}

type ParseBody =
  | { kind: "text"; text: string }
  | { kind: "image"; data: string; mediaType: string }
  | { kind: "share"; token: string };

async function runParse(
  body: ParseBody,
): Promise<{ ok: true; rows: AiRow[]; usedModel: boolean } | { ok: false; message: string }> {
  try {
    const res = await fetch("/api/ai/parse", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(body),
    });
    if (!res.ok) {
      const problem = (await res.json().catch(() => null)) as { error?: string } | null;
      return { ok: false, message: problem?.error ?? "Kunde inte läsa det där." };
    }
    const result = (await res.json()) as { rows: AiRow[]; usedModel: boolean };
    return { ok: true, ...result };
  } catch {
    return { ok: false, message: "Ingen kontakt med servern." };
  }
}

export function AiAddSheet({
  listName,
  catalog,
  onListItemIds,
  shareToken,
  onCancel,
  onConfirm,
}: AiAddSheetProps) {
  const [text, setText] = useState("");
  const [phase, setPhase] = useState<Phase>(() =>
    shareToken ? { step: "parsing" } : { step: "collecting" },
  );
  const [ticked, setTicked] = useState<Set<string>>(new Set());
  const fileInput = useRef<HTMLInputElement>(null);
  const sharedTried = useRef(false);

  const speech = useSpeech(
    useCallback((heard: string) => {
      // Appended rather than replacing: you can say a few things, stop, and say
      // a few more, and you can fix a misheard word by hand in between.
      setText((current) => (current ? `${current}, ${heard}` : heard));
    }, []),
  );

  const show = useCallback(
    (result: Awaited<ReturnType<typeof runParse>>) => {
      if (!result.ok) {
        setPhase({ step: "error", message: result.message });
        return;
      }
      setTicked(initialTicked(result.rows, onListItemIds));
      setPhase({ step: "reviewing", rows: result.rows, usedModel: result.usedModel });
    },
    [onListItemIds],
  );

  const parse = useCallback(
    async (body: ParseBody) => {
      setPhase({ step: "parsing" });
      show(await runParse(body));
    },
    [show],
  );

  // A share opens straight into the parse — the person already chose the image
  // in another app, and asking them to press a second button here would be
  // asking them to confirm the thing they just did.
  useEffect(() => {
    if (!shareToken || sharedTried.current) return;
    sharedTried.current = true;
    let cancelled = false;
    void runParse({ kind: "share", token: shareToken }).then((result) => {
      if (!cancelled) show(result);
    });
    return () => {
      cancelled = true;
    };
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, []);

  async function pickImage(file: File) {
    setPhase({ step: "parsing" });
    try {
      const image = await fileToParseInput(file);
      show(await runParse({ kind: "image", ...image }));
    } catch {
      setPhase({ step: "error", message: "Kunde inte läsa bilden." });
    }
  }

  function confirm() {
    if (phase.step !== "reviewing") return;
    const plan = planAdditions(phase.rows, ticked, catalog);
    if (plan.adds.length === 0) return;
    onConfirm(plan);
  }

  const dialogRef = useFocusTrap<HTMLDivElement>(onCancel, confirm);

  const rows = phase.step === "reviewing" ? phase.rows : [];
  const listRows = rows.filter((r) => r.group === "list");

    setTicked((prev) => {
      const next = new Set(prev);
      if (next.has(id)) next.delete(id);
      else next.add(id);
      return next;
    });
  }

  function renderRow(row: AiRow) {
    const off = !ticked.has(row.id);
    const item = row.catalogItemId ? catalog[row.catalogItemId] : undefined;
    const already = row.catalogItemId ? onListItemIds.has(row.catalogItemId) : false;
    return (
      <li key={row.id}>
        <button
          type="button"
          onClick={() => toggle(row.id)}
          aria-pressed={!off}
          className="flex w-full items-center gap-3 py-3 text-left"
        >
          <span
            aria-hidden
            className={cn(
              "flex h-[22px] w-[22px] flex-none items-center justify-center rounded-md transition-colors duration-150",
              off ? "border-[1.5px] border-line-strong" : "bg-brand text-on-brand",
            )}
          >
            {!off && <UiIcon name="check" size={14} />}
          </span>
          <ItemIcon iconRef={item?.iconRef ?? "1F4E6"} className="text-xl" />
          <span
            className={cn(
              "flex flex-1 flex-wrap items-baseline gap-x-2 gap-y-1 text-body",
              off ? "text-ink-faint line-through" : "text-ink",
            )}
          >
            {item?.name ?? row.name}
            {!row.catalogItemId && (
              <span className="rounded-full bg-warn-tint px-2 py-0.5 text-badge text-warn uppercase no-underline">
                Ny vara
              </span>
            )}
            {already && (
              <span className="rounded-full bg-surface-sunken px-2 py-0.5 text-badge text-ink-soft uppercase no-underline">
                På listan
              </span>
            )}
            {item?.hasAtHome && (
              <span className="rounded-full bg-surface-sunken px-2 py-0.5 text-badge text-ink-soft uppercase no-underline">
                Har hemma
              </span>
            )}
          </span>
          {row.amount && (
            <span
              className={cn(
                "flex-none text-body font-bold",
                off ? "text-ink-faint" : "text-brand-ink",
              )}
            >
              {formatAmount(row.amount)}
            </span>
          )}
        </button>
      </li>
    );
  }

  return (
    <div
      ref={dialogRef}
      className="fixed inset-0 z-50 flex flex-col bg-surface outline-none"
      role="dialog"
      aria-modal="true"
      aria-label={`Lägg till flera i ${listName}`}
      tabIndex={-1}
    >
      <div className="safe-top flex-none border-b border-line bg-surface">
        <div className="flex h-12 items-center gap-2 px-2">
          <span className="flex-1 truncate pl-2 text-title text-ink">
            Lägg till i {listName}
          </span>
          <button
            type="button"
            onClick={onCancel}
            aria-label="Stäng"
            className="flex h-9 w-9 flex-none items-center justify-center rounded-full text-ink-soft"
          >
            <UiIcon name="close" size={20} />
          </button>
        </div>
      </div>

      <div className="flex-1 overflow-y-auto px-4 pt-4 pb-4">
        {(phase.step === "collecting" || phase.step === "error") && (
          <>
            <p className="max-w-[42ch] text-body text-ink-soft">
              Säg vad ni behöver, klistra in en hel lista, eller ta en bild av
              en — till exempel en skärmdump från en annan app.
            </p>

            {speech.supported && (
              <button
                type="button"
                onClick={speech.toggle}
                aria-pressed={speech.listening}
                className={cn(
                  "mt-5 flex w-full items-center justify-center gap-3 rounded-card py-5 text-body font-semibold transition-transform duration-100 active:scale-[0.99]",
                  speech.listening

                  name="mic"
                  size={22}
                  className={speech.listening ? "animate-pulse" : undefined}

              <span className="text-overline text-ink-faint uppercase">
                Eller skriv och klistra in
              </span>
              <textarea
                value={text}
                onChange={(e) => setText(e.target.value)}
                rows={6}
                placeholder={"ägg\n2 l mjölk\nketchup"}
                autoCapitalize="off"
```

- [ ] **Step 3: Implement the action**

In `src/components/list-client.tsx`, add to the `actions` object:

```ts
    /**
     * One AI read, applied.
     *
     * Creates first, then adds, then amounts — the order matters because an
     * `add_item` naming a vara that does not exist yet is an add of nothing.
     * `dispatch` stamps each op through `buildOp`, and the client clock it uses
     * is strictly increasing, so a dozen ops born inside one millisecond still
     * order.
     *
     * Deliberately the ordinary optimistic path rather than the recipe screen's
     * `/api/ops` round trip: the parse already needed the network, and once it
     * has answered, putting twelve varor on a list is twelve taps' worth of
     * work that the outbox has always been able to carry.
     */
    addManyFromAi: (plan: AiAddPlan) => {
      for (const item of plan.creates) {
        dispatch({ kind: "create_catalog_item", item });
      }
      for (const add of plan.adds) {
        dispatch({ kind: "add_item", listId, catalogItemId: add.catalogItemId });
        if (add.amount) {
          dispatch({
            kind: "set_amount",
            listId,
            catalogItemId: add.catalogItemId,
            amount: add.amount,
          });
        }
      }
      toast(`${plan.adds.length} ${plan.adds.length === 1 ? "vara" : "varor"} tillagda`);
    },
```

```ts
import { expect, onListTile, test } from "./fixtures";

/**
 * The AI dialog, against a stubbed parse.
 *
 * The endpoint is routed rather than called, deliberately. What is worth
 * proving here is that what the model said arrives on the list correctly —
 * grouping, unticking, the new vara — and a real call would make that
 * assertion depend on a paid, non-deterministic third party. The parse itself
 * is covered by `src/lib/ai-add/*.test.ts`.

test("reads a list, lets you untick, and adds the rest", async ({ freshPage: page }) => {
  await page.route("**/api/ai/parse", async (route) => {
    await route.fulfill({
      status: 200,
      contentType: "application/json",
      body: JSON.stringify({
        usedModel: true,
        rows: [
          { id: "r0", said: "2 l mjölk", name: "mjölk", amount: { value: 2, unit: "l" }, catalogItemId: "mjolk", group: "list" },
          { id: "r1", said: "ägg", name: "ägg", amount: null, catalogItemId: "agg", group: "list" },
          { id: "r2", said: "krabbklor", name: "krabbklor", amount: null, catalogItemId: null, group: "list" },
          { id: "r3", said: "salt", name: "salt", amount: null, catalogItemId: "salt", group: "other" },
        ],
      }),
    });
  });

  await page.getByRole("button", { name: "Lägg till flera med AI" }).click();
  await page.getByRole("textbox", { name: /skriv och klistra in/i }).fill("mjölk, ägg, krabbklor");
  await page.getByRole("button", { name: "Läs listan" }).click();

  const dialog = page.getByRole("dialog");
  await expect(dialog.getByText("Ny vara")).toBeVisible();

  // The suggestion group is present but unticked, so it must not be counted.
  await expect(dialog.getByRole("button", { name: /Lägg till 3 varor/ })).toBeVisible();

  // Untick the egg, add the rest.
  await dialog.getByRole("button", { name: /^ägg/ }).click();
  await dialog.getByRole("button", { name: /Lägg till 2 varor/ }).click();

  await expect(onListTile(page, "mjölk")).toHaveCount(1);
  await expect(onListTile(page, "krabbklor")).toHaveCount(1);
  await expect(onListTile(page, "ägg")).toHaveCount(0);
  // "Också på bilden" was never ticked, so salt stayed off.
  await expect(onListTile(page, "salt")).toHaveCount(0);
});
```
